<a name="english"></a>

\## 🇬🇧 English Policy



We take the security of our diagnostic infrastructure and the privacy of our users seriously. If you discover a vulnerability within the ScrapTrap Audit Tool or the hosting environment, we appreciate your cooperation in reporting it to us responsibly.



\### 🛡️ Supported Versions

This policy strictly applies to the live deployment operating on our official production environment:

\*   \*\*Live Endpoint:\*\* `https://scraptrap.de`



Because the diagnostic engine is executed entirely server-side as a proprietary framework and is not distributed as downloadable software, legacy standalone local environments are not covered by this policy.



\### 🔒 Reporting a Vulnerability (Responsible Disclosure)

\*\*Do not open public GitHub Issues for security vulnerabilities.\*\* Publicly disclosing a flaw before a fix is available puts high-risk infrastructures at risk.



To report a vulnerability securely:

1\.  \*\*Private Channel:\*\* Send a detailed security report via the secure contact channels or encrypted email addresses specified on the main project profile or the official homepage (`scraptrap.de`).

2\.  \*\*Required Information:\*\* 

&#x20;   \*   A concise description of the suspected vulnerability class (e.g., Server-Side Request Forgery, Input Validation bypass).

&#x20;   \*   A complete, sanitized Proof of Concept (PoC) or raw request payload required to reproduce the behavior.

&#x20;   \*   The potential operational impact on the execution layer.



\### ⏳ Our Commitment

\*   We will acknowledge receipt of your report within \*\*48 hours\*\*.

\*   We will evaluate the technical validity of the finding and apply necessary server-side remediation as rapidly as possible.

\*   We request that you keep all details strictly confidential until the vulnerability has been successfully patched.



\### 🚫 Strict Prohibitions (Out of Scope)

ScrapTrap operates under strict read-only parameters. The following actions are completely out of scope and constitute a breach of this policy:

\*   Executing automated high-frequency brute-force, fuzzing, or destructive denial-of-service (DDoS) campaigns against the deployment server.

\*   Any attempts to compromise underlying system user accounts or host networks.

<a name="deutsch"></a>

\## 🇩🇪 Deutsche Richtlinie



Die Sicherheit unserer Diagnose-Infrastruktur und der Schutz unserer Nutzer haben höchste Priorität. Wenn Sie eine Schwachstelle im ScrapTrap-Audit-Tool oder der zugrundeliegenden Server-Umgebung entdecken, danken wir Ihnen für eine verantwortungsvolle und diskrete Meldung.



\### 🛡️ Unterstützte Versionen

Diese Richtlinie gilt ausschließlich für die aktive Live-Anwendung auf unserer offiziellen Produktivumgebung:

\*   \*\*Live-Endpunkt:\*\* `https://www.scraptrap.de`



Da die Diagnose-Engine als proprietäres Framework vollständig serverseitig ausgeführt und nicht als herunterladbare Software vertrieben wird, sind lokale Altsysteme von dieser Richtlinie ausgeschlossen.



\### 🔒 Melden einer Schwachstelle (Responsible Disclosure)

\*\*Erstellen Sie unter keinen Umständen öffentliche GitHub-Issues für Sicherheitslücken.\*\* Die öffentliche Bloßstellung eines Fehlers, bevor ein Patch eingespielt wurde, gefährdet sensible Infrastrukturen.



So melden Sie eine Schwachstelle sicher:

1\.  \*\*Privater Kanal:\*\* Senden Sie einen detaillierten Sicherheitsbericht über die sicheren Kontaktkanäle oder verschlüsselten E-Mail-Adressen, die im Hauptprofil des Entwicklers oder auf der offiziellen Homepage (`scraptrap.de`) hinterlegt sind.

2\.  \*\*Erforderliche Informationen:\*\*

&#x20;   \*   Eine präzise Beschreibung der vermuteten Schwachstellenklasse (z. B. Server-Side Request Forgery, Umgehung der Eingabe-Validierung).

&#x20;   \*   Ein vollständiger, bereinigter Proof of Concept (PoC) oder rohe Request-Payloads, um das Verhalten zu reproduzieren.

&#x20;   \*   Die potenziellen Auswirkungen auf die serverseitige Ausführungsschicht.



\### ⏳ Unsere Zusage

\*   Wir bestätigen den Erhalt Ihres Berichts innerhalb von \*\*48 Stunden\*\*.

\*   Wir prüfen die technische Validität des Befundes und spielen so schnell wie möglich eine serverseitige Behebung ein.

\*   Wir bitten darum, alle Details bis zum erfolgreichen Abschluss des Server-Patches strikt vertraulich zu behandeln.



\### 🚫 Strikt untersagte Handlungen (Out of Scope)

ScrapTrap operiert unter strengen Read-Only-Parametern. Folgende Aktionen sind ausdrücklich untersagt und verletzen diese Richtlinie:

\*   Die Ausführung automatisierter, hochfrequenter Brute-Force-, Fuzzing- oder destruktiver Denial-of-Service-Kampagnen (DDoS) gegen den Hosting-Server.

\*   Jegliche Versuche, System-Benutzerkonten oder zugrundeliegende Host-Netzwerke zu kompromittieren.
